# eBay 値付け計算機 (PWA)

Play Japan / 有限会社オーシャン貿易 の eBay 輸出向け価格計算ツール。
スマホのホーム画面に追加すると、全画面のアプリとして動きます。圏外でも動作します。

## 置き場の決まり（npm・設定）

リポジトリのいちばん上に `package.json` と `package-lock.json` を置き、
**`node_modules/` は入れない**（`.gitignore`）。

```powershell
git clone …
cd pj_price
npm ci            # package-lock.json のとおりに入れる（版が固定される）
```

* `wrangler` は**いちばん上に1回だけ**入れる。`node_modules` は上の階層へ
  たどって見つかるので、`proxy-sync` など各 Worker の場所からも使える
* 版は `package.json` で**固定**（`^` や `~` を付けない）。
  上げるときは `npm i -D wrangler@<版>` を流して lock ごとコミットする
* **`package.json` に `"type"` を書かない。**
  `"type":"module"` にすると `tests/*.js`（CommonJS）が全部壊れ、
  `"type":"commonjs"` にすると Node の ESM の自動判別が止まって
  `proxy-sync/worker.js`（`export default`）を読めなくなる
* よく使う命令

  | | |
  | --- | --- |
  | `npm test` | テストをぜんぶ流す |
  | `npm run d1 -- proxy-sync/migrate-0031-….sql` | マイグレーションを1文ずつ流す |
  | `npm run d1:all` | **未適用のマイグレーションだけ**を番号順に流す（7.116） |
  | `npm run d1:all -- --dry-run` | 流すものの一覧だけ出す（何も変えない） |
  | `npm run deploy:sync` | pj-sync を出す（`:price` `:img` `:title` も） |

**出先（スマホ）から pj-sync を出すとき**は、GitHub の **Actions** タブの
**deploy-pj-sync** を押す（D1 のマイグレーションとデプロイをまとめて行う・7.116）。
手順と Secrets の登録は `proxy-sync/README.md` の **1-7**。
**画面（`index.html`・`sw.js`・`manual.html`）は GitHub Pages なので、
main に push した時点で自動で出る**（この操作は要らない）。

**Worker の設定（`wrangler.toml`）**：KV の id は**秘密ではない**ので
リポジトリに入れる（それだけでは誰も読めず、読み書きにはアカウントの認証が要る）。
入れておかないと、手元で書き換えるたびに `git pull` でぶつかる。
**秘密（APIキー・トークン・パスワード）は `wrangler secret put` で入れ、
`[vars]` にもリポジトリにも書かない。**

## 公開手順（GitHub Pages）

このアプリはリポジトリ **`pj_price`**（Public）で公開済みです。GitHub Pages は有効です。

- 公開URL: **https://gamegamesan-dot.github.io/pj_price/**
- 設定: **Settings → Pages** で Source = **Deploy from a branch**、Branch = **main / (root)**

ファイルを差し替えて `main` に push すると、1〜2分で公開URLに反映されます（あわせて `sw.js` のバージョンも上げること。下記「更新のしかた」参照）。

Service Worker は HTTPS が必要です。GitHub Pages は HTTPS なのでそのまま動きます。

## 更新のしかた

`index.html` などを差し替えたら、`sw.js` の2行目
```js
const V = 'pj-pricing-v5';
```
の末尾の番号を `v6`, `v7` … と上げてください。これを変えないと古いキャッシュが残り続けます。
（`pj-pricing` はキャッシュ名の接頭辞で、リポジトリ名 `pj_price` とは別物です。変更不要）

**あわせて `index.html` の `var APP_V='vNN'` も同じ番号にしてください。**
こちらは「いま画面に出ている HTML 自身の版」で、フッターに出るのはこの値です。
2つがずれていると、画面が古いままなのに新しい版だと思ってしまいます
（番号がそろっているかは確認用の `ver.js` が見ています）。

### 直したあとの作業の書き方（7.116）

直したあと、何をすればよいかは次の3つに分けて書く。

| 変えたもの | 作業 |
| --- | --- |
| 画面（`index.html` / `sw.js` / `manual.html` / `shared/pricing.js` / `shared/mwcsv.js` / `shared/mwstat.js`） | **main に push すれば GitHub Pages が自動で出す**（操作は要らない。スマホの画面は再読み込み） |
| pj-sync（`proxy-sync/worker.js`） | **GitHub アプリで `deploy-pj-sync` を実行（`dry_run` を外す）** |

PC が使えるときは今までどおり
`cd proxy-sync; node d1-migrate.mjs; npx wrangler deploy` でもよい
（どちらで流しても二重にならない）。

## 確認用テスト

`tests/` に入れてあります。**直す → テストを足す → push** の順で進めます。
以前は作業用の一時フォルダに置いていて、実行環境が入れ替わったときに消えました。
リポジトリに入れてあるので、どの端末でも同じコマンドで走ります。

### 走らせ方

```sh
sh tests/run.sh            # すべて
sh tests/run.sh review     # 名前に review を含むものだけ
node tests/review.js       # 1本だけ（中身の出力も全部見える）
```

`❌` が1つでもあれば終了コードは 1 になります。

### 必要なもの

| もの | 備考 |
|---|---|
| Node 22 以上 | `node:sqlite`（Worker のテストで D1 の代わりに使う）が要るため |
| Playwright と Chromium | 画面のテスト（`*.js`）で使う。`npm i -g playwright && npx playwright install chromium` |

置き場所は `tests/lib.js` が自動で探します。見つからないときは
`PJ_CHROME=/path/to/chrome sh tests/run.sh` のように Chromium の場所を渡してください。
`PLAYWRIGHT_BROWSERS_PATH` が設定されていればその中も見ます。

### 値付けの式を変えるとき

`tests/pricing.js` と `tests/pricing.mjs` は、`tests/pricing-baseline.json`
（**式を変える前**に記録した金額）と1セント単位で見比べます。
式をわざと変える（手数料の実測値を直す、地帯を増やすなど）ときは、
**変える前に**基準を取り直してください。

```sh
node tests/tools/record-baseline.js     # tests/pricing-baseline.json を作り直す
```

`tests/tools/` は一括実行（`sh tests/run.sh` が見るのは `tests/*.js` と `tests/*.mjs`）
には入りません。**いまのコードで取り直すと見比べる意味が無くなる**ので、
うっかり走らせないようここに置いてあります。

- 1項目 = `ok(条件, '説明')` の1行。大事な項目は説明の先頭に `★` を付ける。
- 外に出る通信（Amazon・eBay・pj-sync）は必ず `window.fetch` を差し替えてから使う。
  **本物のAPIは呼ばない。**
- 数字を書き写さず、画面の中で計算させて比べる（設定が変わると当てにならないため）。
- 最後に `T.done()` を呼ぶ。`RESULT <✅の数> <❌の数> <題>` の行を出し、`run.sh` がそれを読む。

## 会員向け Discord サーバーを作る（8.1）

サブスク会員に商品リストを配信するための Discord サーバーを、ボットで自動で作ります。
**社内用の通知サーバー（pj-sync が投げる先）とは別のサーバー**です。
設計は `discord/server.config.json` にぜんぶ書いてあります（直して再実行すれば変わります）。

### 1. ボットを作る

1. <https://discord.com/developers/applications> を開き、**New Application**（名前は `pj 配信ボット` など）
2. 左の **Bot** → **Add Bot** →（必要なら）**Reset Token** を押して**トークンをコピー**
   - トークンは**パスワードと同じ**。人に見せない・ファイルに書かない・チャットに貼らない
   - **特権インテント（Message Content など）はオフのまま**でよい（このスクリプトは使いません）
3. 左の **OAuth2 → General** で **Client ID** をコピー

### 2. 招待する（必要な権限だけ）

次の URL の `（Client ID）` を差し替えて開き、**作ったサーバーを選んで招待**します。

```
https://discord.com/api/oauth2/authorize?client_id=（Client ID）&scope=bot&permissions=2252109319892048
```

入っている権限は **チャンネルの管理・ロールの管理・メッセージの送信・メッセージの管理（ピン留め）
＋チャンネルを見る・履歴を読む・リンクの埋め込み・ファイルの添付
＋リアクションの追加・公開スレッドの作成・スレッドで送信** の11個だけです。
**管理者（Administrator）は入れません**（ボットには持たせません）。

> 後ろの3つ（リアクション・スレッド）は、**読むだけのチャンネル**を作るのに要ります。
> Discord は「自分が持っていない権限は、ロールにもチャンネルにも書けない」決まりなので、
> これが無いと会員向けチャンネルでリアクションとスレッドを止められません（8.7）。

招待したら、**サーバーの設定 → ロール**で、ボットのロール（連携のロール）を
**いちばん上**に動かしてください。Discord の決まりで

1. ボットは**自分が持っていない権限**をロールやチャンネルに付けられない
2. ボットは**自分のロールより上のロール**を直せない・動かせない

ため、ボットのロールが下にあると `HTTP 403 / 400 Missing Permissions（50013）` で止まります。

**「管理者」ロールだけは、人が手で作業します**（ボットに管理者権限を持たせないため）。
スクリプトは「管理者」を作りますが、権限と並びは付けられないので、
実行後に出る **「手でやってほしいこと」** のとおりに

- 「管理者」ロールに **管理者（ADMINISTRATOR）** を手で付ける
- 「管理者」ロールを **ボットのロールより上**に手で動かす

をしてください（1回だけ。次からは「なし」になります）。

### 3. サーバー ID を調べる

Discord の **設定 → 詳細設定 → 開発者モード**をオンにし、
サーバー名を右クリック → **サーバーIDをコピー**。

### 4. 実行する（PowerShell）

```powershell
cd C:\…\pj_price
$env:DISCORD_BOT_TOKEN="（コピーしたトークン）"
$env:DISCORD_GUILD_ID="（コピーしたサーバーID）"

node discord/setup-discord.mjs --dry-run   # 1. 何をするかだけ見る（変えません）
node discord/setup-discord.mjs             # 2. 実行する
                                           # 3. 出た「手でやってほしいこと」をやる
node discord/setup-discord.mjs             # 4. もう一度（「なし」ばかりになるのが正しい）
```

`--dry-run` でも**ボットの権限と位置を先に調べる**ので、
「付けられない権限」「ボットより上に置くロール」は**実行する前に**一覧に出ます（8.7）。

- **何度実行しても二重に作りません**（名前で照合し、あれば権限と並び順だけそろえます）
- **既存のチャンネル・ロール・書き込みは消しません**。設定に無いものは
  「設定にないもの（消していません）」として一覧に出すだけです
- 案内文（#はじめに・#ルール・規約・#お知らせ）は**空のチャンネルにだけ**投稿してピン留めします
- 実行後に **`discord/ids.json`** にロールとチャンネルの ID を書きます
  （あとで pj からの配信やロール付けに使います。`.gitignore` に入れてあるので公開されません）
- 実行の最後に、**ボット自身へ「配信ボット」のロールを付けます**（8.8）。
  案内・リスト・注文・管理-ログのチャンネルは「配信ボット」が書ける設定なので、
  これが無いと案内文の投稿も配信もできません（`403 / 50013`）
- **途中で止まりません**。ロールの作成・並べ替えに失敗しても、
  チャンネルの作成と案内文の投稿まで進み、最後に
  「手でやってほしいこと」「できなかったこと（止めずに進めました）」として
  **原因と直し方**を日本語で出します（8.7）
- まず**テスト用のサーバー**で 1 → 2 → 3 → 4 を試してください

### 5. うまくいかないとき（8.7）

| 出た文 | 原因 | 直し方 |
|---|---|---|
| `POST /roles → HTTP 403（50013）` | ボットが持っていない権限（管理者）を付けようとした | 今は**自動で落として**作ります。「手でやってほしいこと」のとおり手で付けてください |
| `PATCH /roles → HTTP 400/403（50013）` | ボットのロールより上のロールを動かそうとした | サーバー設定→ロールでボットのロールを**いちばん上**へ。管理者だけは手で上に置きます |
| `HTTP 401` | トークンが違う・期限切れ | Developer Portal で **Reset Token** し、`$env:DISCORD_BOT_TOKEN` を入れ直す |
| `HTTP 404` | サーバーID が違う・ボットが居ない | 招待 URL でボットを入れ、`$env:DISCORD_GUILD_ID` を確かめる |
| `50001` | そのチャンネルをボットが見られない | チャンネルの権限でボットのロールに「チャンネルを見る」を付ける |

**ボットに「管理者（Administrator）」は付けません。** 一時的に付ければロールは作れますが、
外したあとに「管理者」ロールがボットの手に負えなくなり、並べ替えで止まります。

### 6-2. 会員向けの配信を始める（8.11・【Y】）

**カジがやること**（上から順に）

1. **ボットのトークンを pj-sync に入れる**
   → `proxy-sync/README.md` の「**1-6. スマホから鍵を入れ直す**」

   - 「モニター：チャンネルID」… 2 でコピーした数字

   - 仕入れタブで「会員に出す」に印 → 販売数の上限と販売価格を決める

## 会員向け販売（Shopify）でカジがやること

pj 側（刈取の「会員に出す」の印・Shopify 用 CSV・英語の翻訳CSV）は
**6.170／7.130** にあります。ここは **Shopify の管理画面でやること**です。
公式ドキュメントは 2026-11-10 に確認しました。

> **まず1件で通してください**：CSV で1件読み込む → 会員タグの付いた
> テストの顧客で**見える** → タグの無い顧客で**見えない** → 1点買う →
> 在庫が減る。ここまで通ってから件数を増やします。

### 1. アクセス制限のアプリ（会員専用にする）

**Shopify の標準機能では「タグの付いた顧客にだけ商品を見せる」ことはできません。**
Markets の条件は国・地域／B2B の会社ロケーション／実店舗／販売チャネルで、
顧客タグは条件に使えません。なので**アプリが必要**です。

- **Locksmith**（Lightward）… 月 $12 から・15日試用。
  **オンラインストア（Liquid）の中だけで効きます**（販売チャネルを
  オンラインストアだけにする前提と合っています）
- 安い候補：autoLock（$9.99/月）／Latch（$4.99〜）／SHOPLOCK（$3.99〜）／
  BSS B2B Lock／Wholesale Lock Manager
- **入れる前にアプリのページで今の値段と対応を確かめてください**

鍵のかけ方：**タグ `member-list` の付いた商品**を、
**顧客タグ `grade-monitor` / `grade-light` / `grade-standard` / `grade-premium`
のいずれかを持つ顧客にだけ**見せる。鍵のかかった商品を一覧・検索・サイトマップから
外せるアプリなら、その設定も入れてください。

### 2. 会員用の自動コレクション（CSV では作れないので1回だけ手で）

1. **商品 → コレクション → コレクションを作成**
2. 名前：`会員リスト`（呼び名は保留なのであとで変えられます）
3. **コレクションの種類＝自動**
4. 条件：**商品のタグ** が **`member-list`** に**等しい**
5. 保存

> 条件つきコレクションは 5,000個まで、1コレクションに条件の元10個・
> 1つの元に値60個までです。

プランごとに見せ分けたいときは、同じやり方で `grade-premium` などの
タグでもう1つ作ります。

### 3. 配送（グレード別の送料）

**カジのストアの前提**（2026-11-11 に確認）
- プラン：**Basic**
- ロケーション：**1つ（文京区）** → 在庫は商品CSVの `Variant Inventory Qty` だけで入る
- 配送の画面：**「配送がマーケットに移行しました」**。
  **マーケットごとの配送オプション**（日本：通常配送・速達）の形。
  配送プロファイルの画面ではない

設計メモ（`サブスク設計メモ_送料.md`・2026-11-11 の追記）のとおり、
**モニター会員はゲームソフト通常版のみ**。法人契約は無いので、
クリックポスト（¥185・厚さ3cm・1kgまで）と
レターパックプラス（¥600・厚さ制限なし・4kgまで）だけを使う。

| 本数 | 送り方 | 会員に請求 |
|---|---|---|
| 1〜2本 | クリックポスト ¥185 | **¥200** |
| 3本 | レターパックプラス ¥600 | **¥300** |
| 4本以上 | レターパックプラス ¥600 | **無料** |

**Shopify は「本数」では段を作れないので、重さで出します。**
ゲームソフト通常版は1本 約110g（pj の CSV の `Variant Grams` に入ります）。

#### ① 会員用の商品のまとまりを作る（`[Shipping]` のコレクション）

新しい画面では、**配送プロファイルの代わりにコレクションで商品をまとめ、
各レートの「商品の条件」でそれを指定**します。

1. **商品 → コレクション → コレクションを作成**
2. 名前：**`[Shipping] 会員リスト`**
   （`[Shipping]` を頭に付けるのは、移行したストアでの決まりの形です）
3. **コレクションの種類＝自動**
4. 条件：**商品のタグ** が **`member-list`** に**等しい**
5. 保存

> 「2. 会員用の自動コレクション」で作る `会員リスト`（鍵をかける用）とは
> **別に作ってください**。中身は同じ条件でも、役目が違います
> （鍵＝見せる相手を決める／`[Shipping]`＝送料のまとまり）。

#### ② マーケットの配送オプションに段を入れる

1. **設定 → マーケット**（または **Markets**）→ **日本** を開く
2. **配送（Shipping）**の customization を開く。
   いまある **通常配送 / 速達** が並んでいます
3. **通常配送** を開いて、**レートを追加**
4. レートの名前は **`通常配送`**（＝いまあるオプションと**同じ名前**）
5. **料金の種類＝重量**（weight）
6. **商品の条件**で **`[Shipping] 会員リスト`** のコレクションを選ぶ
7. 段を入れる（金額は実費に合わせて直してください）

| 重さ | 送料 | 何本ぶんか |
|---|---|---|
| 0 g 〜 250 g | **¥200** | 1〜2本 |
| 251 g 〜 350 g | **¥300** | 3本 |
| 351 g 〜（上限は空） | **¥600** | 4本以上（下の送料無料で ¥0 になります） |

> 本数と段が合うのは、**ゲームソフトを一律 100g で出している**からです
> （pj の⚙「3. 仕入れ」→「ゲームソフト1本の重さ（Shopify 用）」・既定 100g）。
> 1本ごとにばらつく Amazon の梱包重量のままだと、2本で ¥300 の段に
> 入ってしまうことがあります。**この欄を変えたら、上の段も合わせて直してください。**

8. **⚠ 段に抜けを作らないこと**。当てはまらない重さの注文は送料が出ず、
   会員が**買えません**（いちばん上の段は上限を空にする）
9. **⚠ 梱包の既定の重さ**（設定 → 配送と配達 → 梱包、または
   マーケットの配送の設定の中）を **0 g** にする。
   これは **Shopify 自身の設定**で、**商品1点ごとに足されます**。
   封筒ぶんを足したいときは、**pj の⚙「3. 仕入れ」→「会員向け（Shopify）の重さ」
   →「Shopify に出す重さの足し分」**（既定 0g）で足してください

   > pj の⚙「見直しのしきい値・既定重量・梱包」にある
   > **梱包マージン（ゲーム60g／フィギュア250g）は eBay の送料計算用**です。
   > Shopify の重さには足しません（別の欄です）。

10. **⚠ 重さが 0g の商品があると、何本買っても ¥200 の段に入ります。**
    pj の「Shopify 用 CSV を書き出す」は、重さが取れていない行の件数を
    出すようにしてあります。出たら「Amazonで調べる」で採寸を取ってから
    出し直してください

**Shopify の商品CSV に書く重さ**は

| 商品 | 重さ |
|---|---|
| **ゲームソフト**（機種が NS／NS2／PS5 など） | ⚙「**ゲームソフト1本の重さ（Shopify 用）**」（既定 **100g**） |
| それ以外 | **Amazon の梱包重量（なければ商品の重量）＋上の「足し分」** |

ゲームソフトを一律にしているのは、Shopify の送料が**本数ではなく合計の重さ**で
決まるためです（6.183）。⚙を **0g** にすると、ゲームソフトも今までどおり
Amazon の梱包重量＋足し分になります。
**限定版など重いものも機種がゲームなら 100g で出ます**。重さで分けたい商品は、
⚙を 0g にするか Shopify 側で個別に直してください。

#### ③ 4本以上で送料無料（グレードごと）

**グレードごとに基本の送料を変えることは、Shopify の標準機能ではできません。**
できるのは「**送料無料にする条件**をグレードごとに変える」ことです。
メモのグレード別の料金（ライト ¥250／スタンダード ¥200 など）を
そのまま出すには、アプリか Shopify Functions が必要です。
いまはモニターだけなので、**無料の条件**で表します。

1. **顧客 → セグメント → セグメントを作成**。クエリに次を入れて保存
   （名前は `モニター会員` など）

```
customer_tags CONTAINS 'grade-monitor'
```

2. **割引 → 割引を作成 → 送料無料**
3. **方法＝自動割引**（コードを入れなくても効きます）。タイトルは
   会員のカゴと決済画面に出るので `モニター送料無料（4点以上）` など
4. **対象の顧客＝顧客セグメント**で `モニター会員` を選ぶ
5. **最低購入要件＝商品の最低数量**に **4** を入れる
6. 保存

> **「点数と金額のどちらか早いほう」**（メモの検討）にするときは、
> 1つの割引で両方は入れられないので、**同じセグメントに割引を2つ**作ります
> （片方は「商品の最低数量」、もう片方は「最低購入金額」）。
>
> プレミアムを「1点から無料」にするときは、`grade-premium` のセグメントに
> **最低購入要件なし**の自動送料無料を作ります。

7. **⚠ タグを付けた直後はセグメントに入るまで少し時間がかかります**
   （公式に注意書きがあります）。見えないときは少し待って読み直してください

#### ④ 遠隔地（北海道・沖縄・離島）

クリックポストとレターパックプラスは**全国同じ料金**なので、
ゲームソフトだけのあいだは分けなくてよいです。
箱もの（宅配便）を扱い始めたら、同じオプションの中で
**配送地域を分けて**（都道府県で選べます）別の段を作ってください。

#### ⑤ まだ決まっていないこと（設計メモの「決めること」）

| | いまの答え |
|---|---|
| 小型と宅配の線引きを pj が判定するか | **判定しています**。クリックポストの決まり（34×25×厚さ3cm・1kg）で `ship-small` / `ship-box` のタグを付け、Discord のリストにも「送料の区分」として出します |
| 無料条件を点数か金額か | Shopify では1つの割引にどちらか片方。**両方いるなら割引を2つ**（上の③） |
| 遠隔地 | ゲームソフトだけなら分けなくてよい（上の④） |
| 実際の契約運賃 | 法人契約なしなので、クリックポストとレターパックプラスの定価で組んであります |
| Shopify での実装方法 | 上の①〜③。**基本の送料はグレードごとに変えられず、無料の条件で表す**のが Shopify の標準でできる形です |

### 4. カゴに通常の商品が混ざったとき（新しい画面では「いちばん高いもの」）

**カジのストアは新しい画面（マーケットごとの配送オプション）なので、
前の心配は小さくなりました。**

| | 古い画面（配送プロファイル） | **新しい画面（マーケットの配送オプション）** |
|---|---|---|
| 同じ名前のオプション | **足し算**（公式例：$3＋$5＝$8） | **いちばん高いものだけ**を請求 |
| 名前が違うとき | いちばん安いものを足して「Shipping」の名前で出す | オプションごとに別に出る |

なので **会員用のレートの名前を、いまあるオプションと同じ `通常配送` に
そろえてください**（上の②の手順4）。そうすると、

- 会員用の商品だけのカゴ … 会員用の段（¥200／¥300／¥600）
- 会員用＋通常の商品のカゴ … **高いほうだけ**を請求（足し算にならない）
- 通常の商品だけのカゴ … いままでの `通常配送`

> **名前を別にすると（例：`会員配送`）、決済画面に2つの配送オプションが
> 並んで出ます。**会員が安いほうを選べてしまうので、**同じ名前にそろえる**
> のがおすすめです。
>
> ⚠ ただし「いちばん高いもの」は、**重さ**のレートでは
> 「それぞれの発送ぶんを計算して足す」ことがあると公式に書かれています
> （`Weight-based, carrier-calculated, and app-calculated rates are
> calculated for each shipment and then added together`）。
> 会員用の商品と通常の商品が**別の発送になる**組み合わせでは、
> 足されることがあります。
>
> → それでも **会員用の商品だけを買ってもらう運用**（Omakase Ship の通常商品と
> 同じカゴに入れない）がいちばん確実です。まず1件で、
> **会員用＋通常商品を1つのカゴに入れて決済画面の送料を見てください**。
> 足し算になっていたら、会員用は別ストア（または別チャネル）に分けます。

### 5. 商品CSV を読み込む手順

1. pj の **仕入れ（刈取）**タブで「会員に出す」に印を付け、
   販売数の上限と販売価格を決める
2. **「Shopify 用 CSV を書き出す」**
3. Shopify の **商品 → インポート**でファイルを選び、
   **「Overwrite products with matching handles」にチェック**して読み込む
   > 列名は**ストアの「商品のエクスポート」が返す形**（`Handle` /
   > `Body (HTML)` / `Variant Price` …）で出しています。
   > ストアの書き出しが新しい名前（`URL handle` / `Description` / `Price`）
   > だった場合は、⚙「列名の形」を切り替えてください。
4. ロケーションは**1つ（文京区）**なので、在庫は商品CSVの
   `Variant Inventory Qty` だけで入ります（在庫CSV は要りません）。
   2つ以上に増えたら、続けて**在庫CSV**も
   （**商品 → 在庫 → インポート**）。そのときは1件だけ在庫を
   エクスポートして、列名を確かめてから使ってください
5. 英語版は **設定→言語**で英語を足し、**翻訳CSVをエクスポート**してから、
   pj の「英題を入れる」で埋めて、**設定→言語 → インポート**

> `URL handle` は `sub-<JAN>` なので、同じ商品を出し直すときは
> **同じ行が上書き**されます（新しい商品が増えません）。

## 計算式

```
R = 為替レート（円/USD）

■ 米国関税・通関手数料（米国宛 = zone 4 のときだけ加算。非US は 0）
  出典: 2026-09-05 に Zonos Prepay アプリで実測（制度変更で変わる）
  関税率 d      = 0.1374（zone 4）/ 0（それ以外）   ← 関税12.5% + 通関手数料の変動分1.24%
  固定 fixed_us = ¥562 （zone 4）/ 0（それ以外）    ← 通関手数料の固定分
  米国関税額 = 申告額 × 0.1374 + ¥562   （申告額 = 売値 × R。zone 4 のみ／非US は 0）
    例: 申告額 5,000円 → ¥1,249 ／ 10,000円 → ¥1,936（固定562があるため少額ほど負担が重い）

a = R × (1 − 手数料率 − 為替コスト率)
b = R × d
固定計 = 固定手数料 + fixed_us

利益 = 売値×(a − b) + 請求送料×a − 固定計 − 仕入 − 梱包 − 実送料
売値 = (目標利益 + 固定計 + 仕入 + 梱包 + 実送料 − 請求送料×a) / (a − b)
```

「Best Offer 自動拒否ライン」は目標利益 0 のときの売値です（＝損益分岐価格）。米国宛はこの関税分だけ分岐点が上がり、非US（アジア等）は加算されないぶん下がります。
